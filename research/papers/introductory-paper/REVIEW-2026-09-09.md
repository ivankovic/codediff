## A. Blocking — wrong or self-contradictory statements

**A1. The paper says "nine tools" but measures ten.**
Table 4 / Table 7 rows: Unix `diff`, git×4, BDiff, `nvim -d`, diffsitter, difftastic, GumTree =
**10**. The word "nine" appears 9 times (lines 97, 652, 674, 684, 688, 721, 751, 764, and in the
Conclusion). The breakdown sentence at line 655 is also wrong on its own terms: *"Five report at
line granularity only … **Four** report sub-line detail: BDiff, Neovim's diff mode, and the three
AST-aware tools"* — that list has five members. 5 + 5 = 10.
*Fix:* decide the unit of counting (10 configurations of 7 tools reads best: "seven tools in ten
configurations"), then sweep every occurrence including `\CommonFixtures` prose ("the fixtures all
nine scored") and both table captions.

**A2. Section 3.2's opening sentence contradicts itself and drops a `\%`.**
Line 333: *"we analyzed \EditsCommits{} commits, touching \EditsCodeFileEdits{} **code files**, of
which \EditsCodeSharePct{} were **code files**"* → renders as "touching 578,783 code files, of which
31.5 were code files." Two problems: the noun is repeated, and `\EditsCodeSharePct{}` has no `\%`.
Checking `edit_shape_stats.py`: `EditsCodeFileEdits` = code edits (578,783), `EditsFileEdits` =
scored modifications (435,239), `EditsCodeSharePct` = code share of *all* file edits.
*Fix:* "…touching ≈1.84M file edits, \EditsCodeSharePct{}\% of them code files. Of the
\EditsCodeFileEdits{} code-file edits, \EditsModifiedSharePct{}\% were modifications…" — and add a
macro for the all-file-edits total rather than leaving the reader to divide.

**A3. Section 3.2 attributes the edit census to the Curated list; the macro says otherwise.**
Line 333 opens "In the Curated dataset", but `\EditsRepositories` = 7,444 — the Full list.
*Fix:* verify which `MODE=` produced the committed `edit_shape.csv` and correct the sentence.

**A4. "Only two-thirds of the files are actually code files" is not what Figure 1 shows.**
Figure 1 reads Code 55.2%, Unknown 30.0%, Data 12.9%. Two-thirds is defensible only if Unknown is
partly code, which the figure does not say. Compounding it, line 260 calls the whole 7,045,754 a
count of "code files" while §3.1 then says only two-thirds are.
Line 260 also renders as *"a dataset of 7,045,754 code files in 30."* — `\NumLanguages{}` with no
noun after it, and no full stop of its own.
*Fix:* state the code share as a macro from the same source that feeds the pie, and make line 260
read "…\NumFiles{} files in \NumLanguages{} languages".

**A5. The cost analysis hides its third cell, and that cell contradicts §4's framing.**
`\CostScored` 775 = `\CostTieFixtures` 641 + `\CostHumanHigherFixtures` 24 + **110 unaccounted**.
The 110 is already measured and already a macro — `\CostAlgorithmHigherFixtures{}` = 110,
`\CostAlgorithmHigherPct{}` = **14.2** — and `main.tex` never prints either.

It is not a bookkeeping hole. §4 says the comparison used *"a heavily optimized implementation of
APTED"* and RA1.2's box says the human mapping costs more *"than a pure tree edit distance
mapping"*, i.e. an optimum. If it were an optimum, the human could never be cheaper — and on 14.2%
of fixtures it is. The Conclusion already concedes this (*"the comparison mapping was a heuristic's,
so the rate … is a lower bound"*), so §4 and §10 currently contradict each other.
*Fix:* print all three cells; restate RA1.2's box as "than the mapping our matcher found"; drop
"pure tree edit distance" from the box and the "lowest cost tree edit distance" claim from §4's
opening.

**A6. `\AmbiguityFullTotal` (232) ≠ `\SampleFullPromoted` (231).** Section 3.3 says "27 of the Full
list's 232 diffs" two paragraphs after establishing the Full list promoted 231.
These may be different populations (231 promoted + 2 resampled, or stratified fixtures drawn from
Full-list repositories, could each legitimately give 232) — but the paper never says so.
*Fix:* verify whether the two count the same set. If they do, one is stale; if they don't, §3.3

**A6b. RA1.1's denominator is never scoped.** The box reads "11.6% (27 of 232) diffs" with no

**A7. RQ1.2 drifts between its two statements**, which the source comment at line 116 explicitly

**A8. Figure 2's in-image title says "RQ1".** The RQ was renumbered to RQ2 in the 2026-09-02

## B. Structure (`fraser-structure`)

**B1. No Threats to Validity section.** For an empirical SE paper at ICSE/FSE/EMSE this is close to
an automatic reject. The material largely exists already but is scattered as inline caveats (painted
subset not random; corpus adversarially weighted vs real commits; ambiguity rates are floors bounded
by annotator attention; the in-process/external-process timing asymmetry; RA1.2's comparison mapping
being a heuristic's). *Fix:* collect them into §9, grouped construct/internal/external, and leave a
one-line pointer at each original site.

**B2. No Discussion section; interpretation is inside Results and inside the Conclusion.**
Rule 6 wants Results to carry data and analysis, Rule 7 wants a Discussion carrying implications. The
Conclusion currently does both jobs and is ~1.5 pages. *Fix:* lift the six recommendations bullets
and the "most transferable result" paragraph into a Discussion; leave the Conclusion the "so what".

**B3. Heading is "Conclusion and Future Work" (singular).** Rule 8: "Conclusions".

**B4. The title promises a tool paper; the paper is an empirical study.** Sections 3–7 (pages 3–11)
name no CodeDiff by deliberate design; the tool arrives on page 11 of 13. *"CodeDiff: A Fast, Robust,
Production-Ready, Syntax-Aware Code Diffing Tool"* is also three claims wide and "Production-Ready"
is exactly the uncommon-buzzword Rule 1 warns off. *Fix:* retitle around the finding, e.g. *"What a
Syntax-Aware Diff Is Asked to Compute: An Empirical Study of AST Diff Ground Truth"*, with CodeDiff
in the subtitle.

**B5. RQ group 4 is named "Implementation" but contains no implementation.** Section 7 measures
existing tools; Section 8 is the implementation. Two adjacent sections whose names are swapped
relative to their contents. *Fix:* rename group 4 / §7 to "State of the Art" or "Tool Accuracy".

**B6. §2 Background and §9 Related Work cover the same works twice.** GumTree, difftastic,
diffsitter, Unix `diff` and BDiff each get a paragraph in both. §9 is the one doing the comparative
work Rule 2 asks for; §2.2 is closer to a list.
*Fix:* merge — keep §2 for the *algorithms* the paper builds on (ZS, APTED, GumTree, Myers) and move
every tool description into §9, or cut §9's tool paragraph to the deltas only.

**B7. RA3.1 is a bare rate with no supporting analysis.** RQ3.1 is stated (line 561) and answered by
a box on the next line — no methodology, no denominator explanation, no example, nothing between
question and answer. Every other RA has a paragraph or three behind it. This is also the RA the
Conclusion leans on for "*a correct mapping is often not unique*" — 6.7% does not support "often".
The supporting evidence exists and is unprinted: `\CostTieDifferentFixtures{}` (15) /
`\CostTieDifferentPct{}` (1.9) are the format-independent second reading — cost ties between the
human mapping and the matcher's at a *different* mapping — and `\AmbiguityGroups{}` (218),
`\AmbiguityPairs{}` (283), `\AmbiguityPairsPct{}` (2.9) describe the sites themselves.
*Fix:* write the supporting subsection from those macros, and soften the Conclusion's "often" to the
measured rate.

**B8. Only 10 references, and one publishable negative result is missing because of it.**
RA4.1 reports the null — *"Unix `diff` and the four `git` algorithms lie within two hundredths of a
percentage point of one another"* — but never connects it to Nugroho et al.'s published
"use `--histogram` for code changes" recommendation (EMSE 2020), which this data contradicts:
histogram is marginally the *worst* of the four against human ground truth. That is the sharpest
related-work delta the project has and it is absent from `main.tex` entirely. Also missing: the
tree-edit-distance survey literature, anything on code-review reading behaviour to carry §5's
latency framing (the `TODO` at l.472), and any prior AST-diff *ground-truth* work to support §9's
"we are not aware of a corpus that records either".

**B9. The abstract runs to ~450 words and spills onto page 2.** Structure is right (background →
aim → method → results → so-what, no citations, ends quantified), but the four-labelled-part
`\emph{Viability}/\emph{Speed}/\emph{Uniqueness}/\emph{Implementation}` block reads as a table of
contents. *Fix:* cut to ~200 words; keep one number per RQ group.
